## Corrections

### Windows c-ares import contract

Both native install logs and verified manifests contain `lib/cares.lib`, while
`HttpNativeDependencies.cmake` required `lib/cares_static.lib`. In pinned c-ares
1.34.9, `src/lib/CMakeLists.txt` assigns `STATIC_SUFFIX=_static` only inside the
shared-library branch. The existing recipe explicitly uses `CARES_STATIC=ON` and
`CARES_SHARED=OFF`, so its static-only output is `cares.lib` in both configurations.

The import now selects that exact filename. Source selection, recipe, static
MSVC CRT, pins, prefix verification and explicit no-ambient-fallback checks stay
unchanged. Installation/native-resource inventory already consumes the same
`CARES_LIBRARY`, so no second name or copy is introduced. The CMake regression
runs both profiles through the real verifier/import macro with hashed fixture
files and rejects a missing archive. This is a configuration simulation, not an
MSVC link test.

### macOS deployment minimum through LLVM

The native Clang link manifest already included `-mmacosx-version-min=14.0`.
LLVM's `getDefaultTargetTriple()` and ORC's `detectHost()` independently supplied
the SDK/host macOS 26 triple. Consequently AOT objects advertised 26 while the
linker selected 14. The warning was correct; tests rejecting it were correct.

CMake now embeds its explicit deployment minimum in the LLVM backend. One small
triple helper applies that minimum to both native target-machine construction
and ORC construction, before modules/data layouts or cache identities are made.
CPU/features/architecture/vendor/environment remain unchanged. All existing
object emitters use those target machines; native linking still consumes the
same CMake value. The normalized ORC target is part of the existing cache key,
so objects from the old host-minimum identity cannot be reused under the new one.
No deployment target was raised and no warning was suppressed.

The portable triple test covers Apple Silicon, x86 macOS, Darwin spelling,
idempotence and unchanged Linux/Windows/iOS triples. The native-only
`macos_deployment` CTest inspects actual Mach-O load commands for optimized and
unoptimized AOT objects/executables, the architecture-proof object and the
persisted JIT cache object, then checks JIT/cache-hit/AOT execution without
unexpected diagnostics. Its native execution remains pending.

### Upload producer idle time

`write_timer` previously depended on curl reaching the read callback and returning
`CURL_READFUNC_PAUSE`. A producer can already be idle after all admitted bytes
were sent, while curl has not requested the next block. Charging that interval
as socket write inactivity produces the observed `timeout/upload` before resume.
The hosted logs establish the failure signature; they do not record the exact
Darwin socket/callback schedule.

The driver now also recognizes a fixed-length streamed producer as idle when upload is not
finished and its admitted byte count equals curl's sent count for this hop.
Queued/provider-buffered unsent bytes keep the write deadline active. A newly
admitted block reactivates the deadline. Total deadlines, explicit finish,
header/read deadlines, cancellation, file draining and multipart/unknown-length accounting are
unchanged. Unknown-length HTTP/1 chunk framing is included in curl's sent count,
so that count must not be compared with raw producer bytes. No timeout limit was raised.

A native-test-only hook uses curl's real upload rate limiter to defer its next
read callback after the first 1 KiB block. The producer waits 1.1 seconds while
the original write deadline remains **20 ms** and total deadline **3000 ms**.
This models deferred provider callbacks; it is not a claim of native Darwin
execution. With the original predicate restored in an isolated local negative
control, the new regression reports the exact hosted failure signature:
`timeout/upload`, `remote_outcome_unknown=true`, resume elapsed 0 ms. The corrected
predicate passes. The normal 60 ms producer pause, 30 ms blocked-socket timeout,
TLS/proxy phases, Digest replay and file-drain deadline remain checked.
[Original-predicate negative control](evidence/ci41352959359/negative-deferred.stdout).

### Cancellation example fixture

The shared fixture's `/slow` endpoint automatically completed after five seconds.
The cancellation example deliberately awaits another request before cancelling;
a slower JIT/host can reach cancellation after that automatic completion.
The already-completed task then returns normally, with exit 1 and empty stderr.
A six-second barrier delay reproduces that exact outcome on Linux with the old
fixture ([negative control](evidence/ci41352959359/negative-cancellation-before.json)).

The example fixture now holds `/slow` until teardown, bounded by the existing
subprocess/CTest deadlines and `finally` cleanup. The cancellation example's
barrier deliberately waits six seconds, so the regression crosses the old expiry.
The expected `Async task cancelled` diagnostic is still required. Runtime
cancellation semantics and the published example are unchanged.
