## c-ares selected library identity

Python's temporary directory inherits the runner's short TEMP spelling,
`C:/Users/RUNNER~1/...`. The test passed this prefix to CMake and compared its
literal spelling with `selected.txt`. Hosted CMake 3.31.6 instead selected
`C:/Users/runneradmin/...` with the same remaining path. The native import macro
uses `get_filename_component(... ABSOLUTE)`: upstream CMake's
`CollapseFullPathImpl` calls `GetActualCaseForPathCached` on Windows, whose
`GetCasePathName` uses `FindFirstFileW` and `cFileName` to expand real path
components. This explains the spelling change; the original test never queried
whether the OS considered them the same file.

`tests/net/http/ci_triage_test.py` now requires `Path.samefile` for both the
selected archive and its containing directory. It queries filesystem identity,
not case folding, substrings or an alias allowlist. A different archive with
identical bytes must fail identity comparison; a genuine hard-link alias must
pass. Existing deletion/digest-mismatch rejection and both Debug/Release import
checks remain. No production CMake or dependency selection changed. Actual
short/long alias equality is still to be established on Windows by this test.

## mTLS findings and unresolved boundary

Both original native outputs pass ordinary TLS, explicit CA snapshots,
authentication and earlier HTTP operations, then report
`explicit mutual TLS identity: kind=12 code=35`. The failing Windows identity
is **P12**, not PEM: the Windows PEM case already checks the documented
unsupported result. The fixture exports a password-protected P12 using the
pinned test certificate tool. Export succeeds in both original jobs. The
certificate/private key are temporary and were not retained by those artifacts.

VOID snapshots certificate bytes into client-owned bounded storage, supplies
`CURLOPT_SSLCERT_BLOB`, type `P12`, and the password, and retains the client
through transfer cleanup. Pinned curl 8.23.0 Schannel explicitly supports that
representation. Its `get_client_cert` imports with `PFXImportCertStore` and
`PKCS12_NO_PERSIST_KEY`, checks for a private key, and retains the certificate
store with its credentials. Bad P12 import/password is curl error **58**;
credential acquisition and handshake errors can instead produce **35**.
No source evidence establishes a dangling snapshot or unsupported P12 format.

The original logs do not include `SEC_E_*`, an SSPI hexadecimal status,
`AcquireCredentialsHandle` or `InitializeSecurityContext` diagnostics. The
fixture also discarded peer handshake exceptions. Thus curl 35 does **not**
establish the Windows security error or the root cause.

There is a credible backend limitation to investigate:
[Microsoft's PFXImportCertStore documentation](https://learn.microsoft.com/en-us/windows/win32/api/wincrypt/nf-wincrypt-pfximportcertstore)
explains that `PKCS12_NO_PERSIST_KEY` stores a key context that cannot be marshaled
to an external LSASS TLS handshake. [curl issue 17626](https://github.com/curl/curl/issues/17626)
reports Windows Server 2022, curl 35 and `SEC_E_INTERNAL_ERROR (0x80090304)` with
that flag; it is recorded in [curl known bugs](https://curl.se/docs/knownbugs.html).
**That SSPI status is from the upstream report, not VOID's hosted evidence.**
Linux/macOS AWS-LC do not use this Windows credential path. The candidate is
consistent with the platform split, but remains unconfirmed for this run.

No TLS cap, key persistence, credential-store fallback, dependency correction,
certificate-format change or verification bypass has been applied. Removing
`PKCS12_NO_PERSIST_KEY` changes private-key persistence/security ownership;
capping TLS would change approved negotiation policy. Neither is justified by
the current evidence. There is no proven production mTLS repair in this diff.

## Diagnostic and regression changes

- `include/void/detail/http_hooks.hpp`: optional native test provider-error callback.
- `src/runtime/http.cpp`: allocate a curl error buffer only when that callback is
  enabled; retain it through handle cleanup and report failure text before cleanup.
  No ordinary-driver logging, source API change or transport-policy change.
- `tests/net/http/native.cpp`: enable the diagnostic callback; require rejection
  of a missing identity and incorrect P12 password. Existing genuine mTLS
  success remains mandatory, as do other certificate/authentication negatives.
- `tests/net/http/fixture.py`: verify the exported P12 parses with its password;
  capture peer handshake errors, TLS/cipher and authenticated certificate SHA-256;
  require the exact expected client certificate at the peer. Preserve the public
  certificate only. Require one successful identity on Windows, two on other
  backends, a failed anonymous handshake and a captured curl 58 diagnostic.
  Write peer receipts even when the native executable fails.
- `tests/net/http/ci_triage_test.py`: filesystem identity checks and controls above.

Diagnostics do not enable verbose wire logging or key logging and do not retain
P12/private-key material. The callback borrows text, runs on the driver and must
not reenter it. Ordinary drivers do not allocate the optional buffer.
