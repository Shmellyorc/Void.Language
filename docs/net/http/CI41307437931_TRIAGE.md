## Windows: checkout conversion of authenticated bytes

The baseline has no root Git attributes for the vendored tree/review diffs.
Git's actual Windows checkout filter (`core.autocrlf=true`) converts their LF
bytes to CRLF. The Git blob bytes agree with the authoritative manifest.

The read-only control used baseline attributes via `git --attr-source=HEAD`,
then filtered every source/review blob. **1,588 of 1,588** differ from the approved
bytes, and every difference is exactly LF-to-CRLF conversion. See
`windows-all-blobs.json`. The earlier two-file control is `windows-before.json`.
The original host logs do not retain its altered-file hashes; these are local
Git-filter reproduction hashes, not invented hosted payload hashes.

`.gitattributes` now sets `-text` only for `third_party/curl/**` and the two
exact reviewed patch paths. This disables byte conversion while retaining text
diffs. With the current attributes, all **1,588** filtered blobs and working
files match their original approved hashes. No checksum, patch, curl source,
provenance inventory or dependency version was regenerated.

Regression: `CheckoutTests` in `tests/net/http/ci_triage_test.py`, using Git's
checkout filter and the unchanged manifest. This runs as CTest `http_ci_policy`.

## macOS: validate the configuration compiled by curl

`add_subdirectory()` gives curl a child variable scope. Curl sets `USE_OPENSSL`
in that scope; it is not exported into `void_add_curl_provider`. The former
parent test therefore rejects an enabled provider. Cached `HAVE_APPLE_IDN`
alone is also insufficient evidence of the final `USE_APPLE_IDN` setting.

Both original configure logs report AppleSecTrust, IDN and AWS-LC. The cache
records the successful Apple IDN probe and requested OpenSSL-compatible backend.
Curl's `lib/CMakeLists.txt` generates `curl_config.h` before returning; that is
its actual compile configuration, containing `USE_APPLE_IDN`,
`USE_APPLE_SECTRUST` and `USE_OPENSSL` definitions when enabled. The original
macOS artifacts did not retain that generated header.

`cmake/CurlProviderFeatures.cmake` now reads `curl_config.h` from the curl target's
`BINARY_DIR`. All three definitions must be `1`; a missing header or missing/
disabled feature is fatal. Existing pinned AWS-LC prefix verification and runtime
version/feature checks remain in force.

Regressions configure a real CMake child directory and generated header: enabled
features pass even with false parent variables; each missing/zero feature fails
even with true parent variables; a missing header fails. These are local CMake
scope/configuration tests, **not native macOS acceptance**.

The manifest now uses the official versioned fossil location:

The [official release site](https://zlib.net/) and
[archive index](https://zlib.net/fossils/) identify this release/archive.

Independent current acquisitions from the old root URL and official fossil URL
both return **1,502,830 bytes**, HTTP 200, gzip content and the exact approved
SHA-256. Bodies and response metadata are retained in `acquisition/`.
A fresh acquisition through the repaired helper also verifies the same pin
(`acquisition/verified-helper/`). This does **not** establish what the failed
host received. Its bootstrap log retained neither actual hash, size, headers nor
rejected body, and the source cache was a miss. A specific CDN/server/proxy body
or historical endpoint fault therefore cannot honestly be attributed.

The demonstrated acquisition defect is diagnostic loss and promotion of bytes
into the download cache before authentication. `tools/http_archive.py`, shared
by Linux and native dependency recipes, now:

- Verifies cached bytes on every use.
- Downloads into a disposable partial file and promotes it only after the exact
  SHA-256 and successful status checks.
- Records requested/effective URL, response status/headers, size and expected/
  actual hashes. Network failures are recorded too.
- Retains rejected bodies beside the acquisition JSON in the existing build
  receipt directory; HTTP error bodies are retained and rejected.
- Fails without replacing a bad cache entry, changing the pin, retrying through
  another provider or trusting HTTP success alone.

Existing bootstrap receipt collection uploads this evidence on failure. The
new helper and CMake modules participate in dependency cache identity; source
cache identity changes with the URL-bearing manifest. Native recipe manifests
also fingerprint the helper. Installed corresponding-source setup instructions
include it. No production patch application was added.

Regressions use a loopback server for good bytes, HTTP-200 wrong bytes, HTTP
errors, redirects, warm/corrupt caches and a failed acquisition with an obsolete
partial file. Public network access is not required by the regression suite.

## Additional Linux failures: installed compiler loses the pinned IDN closure

The hosted Debug and Sanitizers failures occur on the first relocated JIT run
of `examples/net_http/api_json.void`, before making the HTTP request.

The unmodified baseline reproduces in an Ubuntu 24.04 container with GCC 14
headers/libraries and LLVM 23.1.4. CMake removes the compiler's build RPATH on
installation, without setting an install RPATH. The installed compiler resolves
`libidn2.so.0` and `libunistring.so.5` from `/lib/x86_64-linux-gnu`, despite the
pinned libraries having been installed in `lib/void`. Curl's
`idn2_check_version(IDN2_VERSION)` rejects the older ambient IDN library;
`ProviderLease::require_features()` throws
`Pinned HTTP provider version/features do not match`. The URL ABI catches it as
the reported invariant failure.

`ubuntu-url-rpath-controls.txt` retains loader resolution, the failing original
installed executable, the exact exception from a diagnostic-only runtime copy,
and the successful build-RPATH control. The diagnostic exception print was
confined to a disposable copy; no compiler/runtime source repair was needed.
Earlier diagnostic passes copied build executables and consequently retained
the build RPATH; they were isolation controls, not acceptance of a fix.

`cmake/NativeBuild.cmake` now sets the Linux compiler install RPATH to
`$ORIGIN/../lib/void`. The existing shared libraries and independently linked
AOT resources remain part of the installation. `http_install` now checks the
loader's actual resolution of **both** IDN library families against the relocated
installation before running its original JIT/AOT/native-link/corruption checks.
It performs **18 checks** on Linux (17 existing checks plus loader verification).

Reproducer image: `docker.io/library/ubuntu@sha256:78d4744ead1f5b19b04d0df558ab182a5300903900755e515b2ca4d10eb2044d`.
Image inspection and setup/control logs are retained. The separate diagnostic
container initially lacked `ca-certificates`; its configure rejection is retained
in `ubuntu-install-after.txt`. Installing that required CI package, without any
certificate-check bypass, allowed configuration and the complete repaired
installation test to pass (`ubuntu-install-after-with-ca.txt`). The earlier bad
image-reference and unavailable local `pasta` network-helper controls are also
retained; the local reproducer used Podman's host-network mode.
