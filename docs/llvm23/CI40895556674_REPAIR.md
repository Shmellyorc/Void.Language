## Corrections

**Windows source encoding and the next text oracle.** The six `write_text`
sites in `tests/combined/execution.py` now explicitly select UTF-8. They perform
eleven writes across numeric vectors, console source, unwrap failures, six
negative fixtures, exact error propagation and readonly rejection. At baseline,
cp1252 encoded `é` as byte `E9`; the compiler correctly rejected that source.
This failure was not a Python encoding exception: `é` is representable in cp1252.
There are no corresponding source text reads in this script to repair.

The complete subsequent sequence was audited and executed. `ownership.void`
uses legacy `entry`, whose integer result is printed by CLI `std::cout`
(`src/main.cpp`) and AOT `printf("%d\n", ...)`
(`src/backend/llvm/backend.cpp`). Those are native CRT text. Its three expected
output sites now use the existing `tools/test_platform.py:native_text` helper,
including scenarios 0–6 at O0/O2 in JIT and linked AOT. Captured output is still
compared exactly. The `conversion passed` message uses VOID print and retains
its exact LF. Console input/output, malformed transport byte `FF`, CR/LF cases,
Unicode values, float byte vectors and every negative diagnostic check remain
unchanged. No global Python encoding or newline normalization was introduced.

**macOS rejected filename oracle.** Both original jobs establish creation
rejection with `EILSEQ` (92). Their logs do **not** reveal whether `lstat()`
succeeded or failed with another errno. No native observation is inferred.
Boss explicitly relaxed the requirement for a separate native observation
before repair because no native macOS host is available, and authorized failed
lookup with either `ENOENT` or `EILSEQ`. The next normal Boss-controlled CI run
will supply the actual lookup result; a separate observation-only run is not
required.

`tests/io/kernel.cpp` still requires Apple creation failure to be `EILSEQ`.
It resets errno, captures and logs the actual `lstat()` return value and errno,
and requires failure with `ENOENT` or `EILSEQ`. Lookup success and unrelated
errors fail. Directory enumeration must succeed after rejection and its sorted
entry names must exactly match a successful snapshot taken before the attempt.
The successful-creation branch still requires a real regular file, VOID's
enumeration rejection and successful removal. Both branches still require VOID
metadata validation to return `invalid_path` for the malformed input. Production
filesystem validation and native filesystem calls are unchanged.
