# Slice 7 Gate 5 — Native C callbacks

The checked conventional FFI accepts ordinary VOID functions, bound methods, and literal closures for fixed-signature C callbacks. The independent C fixture exercises multiple integer calls, mixed `double` and `float` arguments, a floating result, and void notifications. A callback may reenter another checked scoped binding on the same thread. A separately qualified retained fixture invokes VOID on a native worker thread. The existing raylib 6.0 gallery receives and validates a real raylib trace message before creating its window.

## Contract and ABI

A conventional revision 2 or 3 descriptor can opt into `effects direct-sync blocking checked-callbacks`. A declaration such as `callback integer context-first i32 i32` specifies the return and parameter shapes. The C function pointer takes its opaque context first. The provider binding expands its last logical argument, `scoped:integer` or `retained:integer`, to the typed callback pointer followed by its `void *` context. The generated VOID declaration accepts the corresponding `func(i32) -> i32`. Callback shapes admit fixed scalar types and void returns. A callback operand must be the last supplied argument and originate in a directly named function, bound method, or literal closure from the current generation.

`voidc native-bind` emits a C11 function with the declared C signature. The generated adapter checks the independently compiled provider header with `_Generic`, including the callback pointer and context. Clang applies Linux SysV or Windows x64 MSVC argument and return rules at the real C boundary. The adapter copies scalar bits through a private word transport to a generation-local LLVM function that dispatches the already checked VOID callable. Source code handles typed VOID callables and managed resource owners. Typed IR independently requires direct calls to the admitted wrapper, an exact callable signature and generation-local provenance, and rejects a raw import of the Runtime bridge.

The scoped provider must finish every invocation before returning and must call on the thread that entered the binding. A retained callback is admitted only on a resource acquisition. The C provider must publish the pair safely, return a new owner on success, retain no pair on null acquisition, and use its matching terminal release to unregister and quiesce. The barrier includes any worker that has already reserved the callback pointer and context but has yet to reach the Runtime. Native code calling the pair after this barrier violates the provider contract.

## Runtime and retirement

The native call enters NativeSafe. The callback context owns a persistent capture root, the precise function identity, the generated entry and a lease on its original code generation. `CallbackRegistration` authorizes attachment and the transition back to Managed. The existing VOID function prologue roots its managed inputs. A compatible body-only reload keeps live callbacks on their original generation. An incompatible native callback descriptor is rejected during compatibility preflight. Unregister releases the original ORC generation only after the provider returns from its barrier and Runtime callback admission has drained.

Terminal release seals callback admission before handing control to the provider. Runtime shutdown closes its existing resource ledger and uses the same terminal release. The test fixture exercises a worker paused before callback admission and another already inside compiled VOID when release starts. The first receives the C failure sentinel while the provider joins it. The second returns its actual result before the provider frees the owner. A retained callback trying to close or borrow its own registration is rejected before it can wait on that resource’s dispatch lock. Reentry through another scoped binding is supported.

Checked failures stay inside the bridge. The C trampoline returns numeric zero or a void return after a failure. The provider must accept that fallback safely. The Runtime records the fault and rejects later callback entries. A scoped call reports the copied VOID failure after C returns. A retained callback fault surfaces as a checked resource operation error or as an error after shutdown drains the provider. Native C++ exceptions and nonlocal jumps across the boundary are outside this contract. A foreign callback is subject to the existing resource owner-thread checks. Shared mutable captured data requires synchronization with other access by the application and provider.

The design reuses the existing Runtime attachment and ORC lease model. libffi closures would add an executable closure and separate retirement problem for this fixed-signature, generated-adapter case. Go cgo’s opaque handles, Rust’s unregister guidance, and Odin and Zig’s explicit C calling conventions support keeping the native entry separate from the managed environment. The independent Research Clanker also verified the raylib global setter and the target-specific `va_list` issue. ## Reproduce

With the pinned Clang/LLVM toolchain and an existing configured build, build the compiler and reload harness. The test runs public `native-bind`, `check`, `run` and `build` against a regular VOID project. It compiles the provider and generated C adapter separately. To retain binaries and generated files, set `VOID_G5_EVIDENCE_ROOT` to a writable directory on the local filesystem.

```sh
cmake --build /path/to/configured/build --target voidc void_g5_reload
ctest --test-dir /path/to/configured/build --output-on-failure -R '^ffi_g5_callbacks$'
```

The harness moves each AOT package to a path with spaces and `雪`, renames the source project and compiler installation, and runs from an independent directory with a system-only PATH. The standalone package contains the executable and its provider and adapter in `native/`. It uses the existing Gate 4 loader and system runtime requirements.

The gallery uses the same preparation and run commands as the prior integration. Add `-- --trace-only` to a JIT run or `--trace-only` to the emitted executable. The trace proof prints `RAYLIB trace invoked VOID`. The normal gallery continues into its existing rendering loop after the proof. [Gallery build guide](SLICE7_RAYLIB_INTEGRATION.md#build-and-run-the-sample)

## Terminal release transport refusal

The defect reproduced on Linux Release with the opening runtime. The reload harness registered a bound callback and invoked it on a native worker before and after a compatible replacement. A separate test adapter refused the first terminal release immediately before the call to `g5_unregister`. The refusal kept both generations live. The next native-worker call reached the retained pair and returned the C failure sentinel `0` where the original callback should have returned `44`. The retry reached the provider once, drained the registration, and retired the original generation. [Original failure log](evidence/slice7-g5-release-refusal/linux/original-test.txt) · [Original JUnit receipt](evidence/slice7-g5-release-refusal/linux/original.xml)

G3 defines a nonzero thunk return as transport refusal before the C operation executes. The generated adapter returns zero after invoking C and writes the C function’s own status to the result word. For a `consume-always` release, an accepted call consumes ownership and must unregister and drain the callback pair even when that status reports a provider error. A thunk that reports refusal after consuming ownership or altering the registered pair violates the transport contract. [G3 ownership contract and direct controls](SLICE7_G3_FINAL_CLOSEOUT.md#acquisition-and-release-ownership) · [G5 descriptor](../../tests/ffi/callback.descriptor.in)

`Resource::close()` still seals admission before dispatch. On transport refusal it restores the exclusive claim and reopens admission only if the callback has no recorded fault. The restoration and fault recording share `error_mutex_`, so a fault recorded before restoration keeps admission sealed and a later fault seals it again. The refused path retains the native pointer, wrapper and capture roots, registration, and both acquisition-generation leases. The resource mutex serializes the seal, restore and consume transitions. Runtime shutdown closes job admission and waits for existing native jobs before draining the resource ledger. It can therefore retry a refused close on the retained owner, and a successful explicit close erases the consumed owner before its job ends. The Runtime also independently rejects new callback entries once shutdown starts. [Exact corrective patch and regression fixture](evidence/slice7-g5-release-refusal/source.patch) · [Runtime shutdown ordering](../../src/runtime/coordination.cpp)

On accepted release the provider barrier covers workers that reserved the callback pair as well as callbacks already in VOID. After the provider returns, `CallbackRegistration::close()` closes Runtime admission and waits for its in-flight count to reach zero before the capture root and callback-generation lease are destroyed. The resource then drops the wrapper and retires its acquisition lease. The original G5 barriers still produced the C fallback for a worker held before admission and the computed result for a worker already inside VOID. [Provider barrier fixture](../../tests/ffi/callback_fixture.c) · [Runtime callback drain](../../src/runtime/callback.cpp)

The corrected fixture checks that the native worker returns `44` from the original callback after refusal and that the original generation retires on retry. A second registration faults by attempting self-unregister. After a refused release its probe callback remains sealed, and shutdown reports the recorded fault after the accepted retry drains it. The instrumented adapter is confined to the reload harness. The existing G5 process cases use the standard generated adapter for normal and optimized JIT and relocated AOT. The regression selection includes the G3 ownership, refusal/retry, shutdown race, and accepted provider error controls.
