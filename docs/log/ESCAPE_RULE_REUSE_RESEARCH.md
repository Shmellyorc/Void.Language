# Logger escape-rule reuse decision

5 November 2026 · Research at `da2edda0` · LLVM 23.1.4

**HOLD on validating the native rules once per application. GO for Wrench design review of one narrower candidate:** when a short input provably contains none of the supplied keys, validate the two lists in place and return the existing string. This could remove construction and destruction of the rule map for ordinary messages while preserving the public text contract. Its speedup is unmeasured. File200 remains open.

## What is already reusable

The logger already initializes two private, application-rooted lists once. I checked their literals: the 81 keys are strictly increasing. Their only consumer in production log source is `_quote`. It checks the remaining byte budget first and returns immediately on empty input. File200 uses an empty name and repeats a 64-byte printable message, giving **one translation per record**, all 200 returning the input alias. A normal nonempty logger name can require a separate translation under a different budget. [Logger source](../../stdlib/log.void#L348) · [File workload](../../tests/log/benchmark.void#L55)

The Runtime currently validates registered slots and schemas, leases both list backings, validates each key and replacement, and copies replacement bytes into an invocation-local ordered map. The map owns native bytes across NativeSafe work. The unchanged-result branch already revalidates the output and publishes the rooted input. A `BufferReadLease` freezes the selected backing for its scope. An alias can grow the list onto another backing. [Translation](../../src/runtime/text_case.cpp#L144) · [Lease](../../include/void/runtime.hpp#L346)

**A rooted list is still mutable.** An indexed replacement can change either a key or a replacement string without changing list identity, count, backing or structural version. Holding leases across calls would make previously legal writes fail. Private visibility and readonly parameters provide no immutable-content certificate to the native text operation. Independent application Runtimes own separate cells. Compatible body reload preserves existing cells, while initializer-contract changes require restart. The approved worker restrictions do not make a process-global or thread-local cache application-owned. Persistent handles would extend lifetimes, and borrowed byte views or registered root words cannot be saved for later calls. [Indexed write](../../src/runtime/array.cpp#L137) · [Global ownership and reload](../RUNTIME_GLOBALS.md#reload-cache-and-tooling)

## Options and candidate

| Option | Review disposition |
| --- | --- |
| Prepare a native map at startup or first use | Requires an enforceable immutable pair, application ownership, publication and disposal. Startup preparation can move allocation or validation failure ahead of the first log call. Comparing all live values on every cache hit still requires root and content checks. HOLD under the current contract. |
| Scan in VOID before calling translation | ASCII alone is insufficient: quote, backslash, DEL and controls escape. A conservative printable-ASCII check can fall back on every non-ASCII byte. Existing shape-0 measurements put the checked byte loop over **already prepared** bytes at 20.609 ms versus 4.708 ms for quote200. These are different operations, not timings of a proposed predicate, but they give little reason to add a per-record UTF-8 conversion and source loop. [Component receipt](evidence/llvm23-framing-20261104/results.json) · [Stage definitions](../../tests/log/performance_framing.void#L64) |
| Remember the last plain message or quoted name | File200 repeats one message and already skips its empty name. A message memo would retain application text and reward repetition without serving distinct ordinary messages. A quoted-name cache cannot improve this workload. |
| Validate without building the map for a bounded no-match case | **Review this candidate only.** It works for distinct messages and any eligible rule table. All state lives within the current call. |

Inside the existing translation operation, after the regular root/schema/count checks, record the ASCII bytes present in a short input in two machine words. Use the already leased arrays. A small sorted table admits a single ordered walk: check every scalar's validity and strict increase, validate every replacement's string identity/extent, and test each key against the presence bits. Only a fully valid, disjoint table qualifies. For a matched key, non-ASCII or long input, non-increasing keys, or work beyond the existing quotas, use the existing general path on the **same selected backings**. Unsorted valid tables remain legal. No logger policy needs copying into C++.

Bound the speculative walk before touching large payloads (for review, at most 128 input bytes, within the existing 256-rule and 16 KiB cooperation quotas). Keep heap borrows inside checked Managed access, release leases at the normal boundary, retain GC cooperation, and reuse the existing final root validation. An unchanged result still needs a nonnegative budget and sufficient byte allowance. Invalid rules take precedence even on empty input or with a negative budget. A failed probe must leave aliased output untouched and fall back before inspecting later entries that could mask the original failure. Allocation or invariant failures on work actually performed must retain the Runtime failure channel. Removing an unnecessary allocation can change an injected failure ordinal. If Wrench requires the original snapshot allocations as observable behavior, stop this candidate. [Rule/error order and publication](../../src/runtime/text_case.cpp#L201) · [Existing ABI ownership checks](../../tests/text_encoding/ownership.cpp#L51)

## Expected benefit and review gate

In one instrumented file200 observation, translation took **5.944 ms**, including **4.411 ms** in the rule loop and **0.748 ms** in disposal. The **5.159 ms** combined includes validation the candidate must keep. Input lookup took about **0.121 ms**. An independent reduced-timer write-only observation measured **4.934 ms** for the whole translation. These scopes give a few milliseconds of plausible opportunity per 200 records, with zero or a regression still possible. They are not additive or predicted savings. The shortfall from the uninstrumented **20.091 ms** median to the strict **<10 ms** requirement exceeds **10.091 ms**. The rejected allocator's **0.605 ms / 3.0%** full-workload gain makes map allocation counts alone a poor acceptance metric. [Attribution](SMALL_FILE_INVESTIGATION.md#translation-follow-up--golden-wrench-review-pending) · [Decision and controls](LOG_PERF_DECISION.md)

If separately authorized, compare repeated **and distinct** short plain inputs, short escaped strings, Unicode, unsorted/duplicate/mutated rules, invalid budgets and aliased output under GC. Keep normal/O2 JIT and linked AOT byte/error oracles. Use the original full file200 control protocol with acquisition, 200 writes, fsync and close included. Retain the heavy framing **≤10 ms** and console **≤20 ms** screens. Discard if the full-workload improvement is indistinguishable from variation, repeats only the rejected small gain, or compromises any correctness or heavy-path gate. An improvement short of the file threshold must remain recorded as a **file200 FAIL**.

Only this research note was created. The assessment uses existing measurements. Implementation and new performance runs await Golden Wrench review and Boss authorization.
