## Why this call site

On Release/LLVM 23, 100 heavy 1-KiB messages took 922.152 ms for quoting, 910.628 ms for framing, 947.525 ms for full console logging and 7.946 ms for prepared console output. These independent stage medians locate the expensive work in record preparation. The separate counting run observed 2,509,955 ordinary C++ allocations and 77,100 managed constructions during framing. Source inspection shows where each escape can create a replacement array, a slice and a transactional stream write. [Quote implementation](../../stdlib/log.void#L376) · [Stream write](../../stdlib/io/memory.void#L165)

**Hypothesis to test.** Scanning validated snapshots and assembling unchanged spans and replacements in bulk may reduce this cost enough to meet the thresholds. The current measurements leave the division of time among metadata lookup, locking, polling, copying and collection unknown. Historical schema-key and flat-builder experiments missed the screens, and the flat builder regressed occasional escapes. The file200 result also needs its own control. Prepared file output took 11.662 ms on a host with a 10 ms absolute screen. [Historical comparisons](HOTPATH_REVIEW.md#escaped-text) · [Original file and direct-I/O workloads](../../tests/log/benchmark.void)

## Safety contract

| Boundary | Required observable behavior |
| --- | --- |
| Ordering | Preserve eager caller evaluation. Filter before reservation. Invoke an admitted lazy builder exactly once, after reservation. Preserve guard ownership through synchronous preparation and asynchronous delivery. Sample and format UTC before framing when timestamps are enabled. |
| Formatting | Preserve the severity label, optional UTC prefix, delimiters, quoted name and message, and exactly one terminal LF. Preserve quote/backslash escapes, short LF/CR/tab escapes, lowercase hexadecimal controls and the precise C1, bidi and separator set. Preserve other Unicode bytes without normalization. Replacement bytes are never recursively translated. |
| Budget | Keep overhead checks, name-before-message order and subtraction of the quoted name’s actual byte length. Exact fit succeeds. One byte over returns `failure_kind.record_too_large`, operation `"frame"` and message `"Encoded record exceeds its byte budget"` before any sink effect. Honor explicitly raised limits. |
| Ownership and GC | Root inputs, arrays, referenced strings and result throughout allocation and safepoints. Validate owner/thread/frame, schemas, extents and reference authority. Acquire stable rule-array leases in a defined order until native-owned snapshots are complete. Bound lookup preparation and traversal with work quotas. Reacquire borrows after polling. Only owned native data may cross a Managed/Native transition. Stage aliased inputs before publishing output. |
| Failure | Unequal counts, duplicate keys or invalid Unicode scalars yield `text.error_kind.invalid_argument`. A negative budget yields `text.error_kind.invalid_range` and excess output yields `text.error_kind.limit_exceeded`. Map that limit to the existing logger failure. An invalid internal escape table is an invariant defect. Allocation/root/invariant failures use the Runtime failure channel. On every failure release temporary storage, roots and leases, preserve caller inputs and leave output unpublished. |
| Output and sink state | Publish one complete immutable string through the checked constructor. Prepare the whole record before touching sinks. Preserve console-first dispatch, the independent file attempt, rotation, partial-write receipts, fault state, explicit-close semantics and cancellation cleanup. A post-effect failure must preserve recorded progress and the existing retry rules. |

The ordering references are the current write, lazy and async entry points and both delivery functions. The ownership precedents are the scoped array lease and checked string publication. If bounding final publication needs a new string builder or lease contract, bring that specific expansion back for review. ## How to evaluate a future candidate

First compare complete bytes and failure results with the current encoder and independent oracles. Cover empty and unescaped strings, occasional and heavy controls, mixed Unicode, exact-fit and one-byte-over records. Exercise malformed roots and rules, aliased output, concurrent/forced GC and injected allocation failure. Recheck filtering, lazy invocation, UTC failures, sync/async delivery, partial writes, rotation and cancellation. Require normal/O2 JIT and independently linked AOT behavior before judging a speedup. [Logging oracles](../../tests/log/oracles.py) · [Transport, failure and benchmark host](../../tests/log/host.cpp) · [Text ownership tests](../../tests/text_encoding/ownership.cpp)

Compare baseline and candidate on the same host with Release/LLVM 23.1.4, GC budget 256, hard/soft 1 MiB stacks, one warmup and three measured repetitions per cell. Time compilation separately. Report median and range, CPU time, byte and transfer counts, and post-GC heap/handles. Count allocations in separate runs. Include rule initialization and snapshot costs in the full logger measurements. Retain the contemporaneous prepared-I/O controls and the wider ASCII, Unicode and near-budget shapes.
