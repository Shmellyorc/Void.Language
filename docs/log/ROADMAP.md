## Ordered engineering sequence

These are internal steps of one complete sprint, not repeated approval checkpoints or independent mini-sprints.

1. **Settle the actual contract decisions.** Confirm trusted single-owner namespace plus explicit adoption/alias warranty, and checked convenience results with conservative transport faults. Approve the complete API/defaults as one contract. If Boss instead requires hostile-namespace identity safety, specify the smallest existing-io enhancement first; do not implement an unsafe source approximation or remove retention tests.
2. **Establish public source shapes end to end.** Add the normal module types/signatures, private logger construction, scalar/string/value configuration, typed nullable failure causes and memory-only default global. Verify source→IR→JIT/AOT for mutable receiver fields, result<bool,failure>, private lifecycle, closures and async-safe receiver layout early. `failure`, not `error`, preserves the named severity function. Keep compiler-owned visibility and readonly diagnostics.
3. **Implement the shared admission/framing path.** Five severity wrappers call one synchronous engine; lazy and async paths reuse the same validation, threshold mapping, quote/budget and timestamp helpers. Filter before log-owned work, invoke lazy body once, format through existing language facilities, and encode one bounded byte record. Validate Unicode controls and byte limits without per-scalar rescans or quadratic concatenation. Separate sampling the clock from pure framing so fixed instants can exercise exact bytes without a public clock-plugin API.
4. **Implement source reservation and lifecycle guards.** Register cleanup before setting busy/acquiring resources, using the existing I/O lease/acquisition pattern. Same-instance admitted recursion/concurrent owner activations fail busy; guards release on all exits. Fault conservatively on uncertain transport/mutation completion. Give logger direct deinit; no implicit recursive cleanup or Disposable type. Distinguish recoverable errors from Runtime unwind/cancellation and preserve original failures.
5. **Deliver complete console emission.** One borrowed output call per record, stderr default, optional stdout/none, existing redirection, no terminal capability framework. Return actual complete/partial outcomes. Preserve independent instance settings and the one application-default global; do not introduce a process-wide logger registry.
6. **Acquire persistent files safely within the chosen contract.** Absolute path snapshot, full exact-set preflight, exclusive fresh creation, explicit checked adoption, regular-kind and size/LF validation, no implicit parent creation or truncation. Use acquisition cleanup so failure/publication allocation cannot lose a live native resource. Document any empty created file left after failed acquisition; do not erase paths opportunistically.
7. **Complete rotation and reconfiguration.** Byte-count admission, reject oversized encoded records, flush/close before native same-directory renames, exact oldest removal, descending no-replace moves, exclusive new active file. Implement N=0, holes, existing collision, every failed mutation boundary and explicit recovery. Handle live backup-count changes using only known owned names; preserve old-path history on path changes. No overwrite/copy/delete rollback. Failed configuration cannot silently continue in a partial mode.
8. **Complete checked flush/close and shutdown.** Attempt file close after a recoverable flush error; preserve both native causes and console errors. Idempotent closed behavior, busy ownership retention and retired-close semantics must match io. Install reached synchronous final-close fallback for Runtime failure. Deinit can raise the existing generic Runtime diagnostic; important cleanup examples inspect typed results explicitly. No source logger destructor is assumed at Runtime teardown.
9. **Deliver all explicit async file-operation variants.** Acquisition, validation, metadata, tail checks, rotation, write, flush and close await current io async APIs. Keep bytes/handles rooted and busy until completion. No callback fields/async lazy parameters. Document body-time configuration selection and synchronous console portion. Cancellation must drain already-entered native work before final close; no duplicate record retry or orphaned resource after cancellation.
10. **Integrate globals, GC, cache/reload and installation/tooling.** Default import/analysis has no I/O. Preserve fresh-runtime state and compatible reload persistence; rebind only after old ownership is handled. Add compiler-owned docs and standard import/member discovery. Reuse source installation and relocated-tree checks. Do not modify editors with logging lists or execute startup through LSP.
11. **Finish focused verification and measurements.** Use the matrix below while engineering, then one consolidated feature/adjacent regression selection after completion. Debug, Release and strict profiles; normal/O2 JIT and independently linked/executed AOT; explicit async-root runner where required. Repair concrete failures, preserve their original evidence, and rerun only affected checks until justified integration coverage is complete.
12. **Prepare the Wrench handoff.** API inventory/capability matrix, exact changed files, binary/source hashes, commands, profile/mode/stack/platform receipts, bounded timings/memory, incident history and true remaining native limitations. Update internal index/contracts as needed. Stop for review. Boss alone handles Git and later hosted standard-library integration CI.

Keep sync/async differences at existing I/O boundaries. Common source helpers own policies; source receiver methods own state. Avoid a generic effectful I/O interpreter just to remove superficial duplication. If a newly exposed shared compiler defect blocks correct lowering, preserve a small reproduction and repair only the reviewed shared cause; do not add a log-specific type/effect bypass.

## Bounded performance and memory plan

Measure Release normal/O2 JIT and linked AOT separately from compilation. Start with three repetitions of a bounded workload, with warmup and a checksum/counter preventing dead-code removal:

- Disabled direct string, disabled eager formatted/custom-display message, guarded message, lazy named callback and captured builder: 10,000 calls, record builder/hook/factory counts and allocations.
- Enabled stderr redirected to a test endpoint and a real file, timestamps on/off, 64-byte/1-KiB/near-limit records: at most 1,000 records per case. Compare direct console/io baseline with identical bytes.
- Sync flush once versus selected explicit flushes; small-threshold rotation through 20 cycles with 0/3/32 backups. Record write/flush/metadata/move/delete counts and bytes.
- Sequential awaited file emission: bounded 100/1,000-call cases plus repeated roots, measuring live objects/provider resources, frame retirement and retained task records. Separate process high-water RSS from per-record/module allocation.

Report median/range, wall and CPU where available, clean source→IR/JIT/AOT compile time, transient allocations, peak live bytes/stack and native operation counts. No fixed throughput target without a measured baseline. Require linear framing growth, no log-owned work in the filtered synchronous path beyond admission/state/result costs, no native metadata call per ordinary exclusive-writer record, bounded current-file retention and no unexplained post-root resource growth. Do not infer constant RSS from absence of a logger queue. Broaden measurements only when a demonstrated regression needs it.
