# Logger heavy-path regression investigation

5 November 2026. **Cause of the measured slowdown: UNKNOWN.** The rejected implementation does extra work on long messages, and the affected Runtime function has different native code. The receipts establish neither contribution in milliseconds. **GO for Wrench review of one length-dispatch correction. HOLD the rejected patch and the release gate.** This investigation inspected existing files and binaries only.

## What the heavy workload executes

The heavy case formats 100 messages of 1 KiB containing escape characters. The configured name is empty, so its quote call returns before translation. Each message reaches the translator with 81 keys. The rejected patch first performs normal root/schema validation, acquires the two leases and checks their counts. Because 81 passes the 256-key cutoff, it then locks the Runtime mutex again, resolves the input root again and reads the managed string extent again. Only then does the 128-byte cutoff send the message to the general path. **No heavy message executes the ASCII presence scan or speculative rule walk.** Its ordinary 81-rule snapshot, translation and publication still execute. The patch also changes the general loop's source condition and adds a post-lease result branch. [Rejected patch](evidence/no-match-20261105/candidate.patch) · [Workload](../../tests/log/performance_framing.void#L13) · [Logger framing](../../stdlib/log.void#L376)

I matched the SHA-256 of all four timed hosts to the receipt. Offline disassembly of the retained candidate object confirms the mutex lock at object offset `0xe59`, root resolution and string lookup, length comparison at `0xe88`, and long-input exit through the unlock at `0xfec`. The short probe was compiled into the shared translator. In the linked component host its symbol moved from `0x23dba00` to `0x23dba40` and grew from 5,409 to 5,918 bytes. The two object prologues reserve the same 696 stack bytes but assign arguments to different registers. These are observed native code and layout differences. The disassembly does not establish a cache miss, branch misprediction, lock contention, or 81 extra optional-value tests per message. The changed object was compiled C++ Runtime code. The measurement drivers linked it against the same component host object and libraries. ## One correction worth reviewing

**Dispatch using the byte length already obtained during mandatory input-root validation.** Carry only a scalar eligibility hint out of that lock. After the common root/schema/count and lease setup, long inputs proceed directly into the original map-building loop. Put the short probe out of line and select the general loop outside its iteration condition. A short miss must fall through using the same selected backings. Verify the compiled long path actually bypasses the helper and the second lock/lookup. Moving the cutoff to the beginning of the existing lambda still requires the second lookup unless the validated length is carried forward. [Existing initial validation](../../src/runtime/text_case.cpp#L144) · [Existing leases and general loop](../../src/runtime/text_case.cpp#L180)

This isolates **execution** of the short proof. A dispatch branch and a different link layout can remain. Identical heavy timings or instruction addresses cannot be promised. Short plain inputs should retain the map-avoidance benefit, with the cost of a helper call. The heavy path would lose the confirmed redundant work. Recovery of the measured 9.4% or 4.2% is unverified.

**Safety boundary.** The saved length grants no authority over a pointer or string view. Re-resolve the registered input on the eligible path and confirm its current bounded extent before scanning. Keep one common validation/lease acquisition and one general fallback. Preserve the original selected backings across an inconclusive probe, reference-before-key error ordering, complete rule validation before budget errors, byte/rule quotas, GC cooperation, NativeSafe disposal and final checked publication after lease release. Invalid or aliased outputs must remain untouched on failure. Logger budgets, bytes, sink order, fsync and close stay part of acceptance. [Translation and publication](../../src/runtime/text_case.cpp#L201) · [Existing ownership controls](../../tests/text_encoding/ownership.cpp#L51)

**Stop conditions for any later authorization.** First inspect the optimized long path statically. Stop if isolation needs duplicate validation, another lease acquisition, weaker safety checks or a new Runtime contract. Only after separate authorization would matched whole-workload controls be justified. Require distinct as well as repeated short strings, existing JIT/AOT failure and ownership oracles, and retained heavy no-regression evidence across balanced blocks. Discard if the heavy regression persists, any heavy console block again fails the reviewed screen, or the short gain disappears into control variation. Keep the original file200 **<10 ms**, heavy framing **≤10 ms** and heavy console **≤20 ms** requirements. A partial file200 gain remains a failed file gate.
