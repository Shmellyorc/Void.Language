## 2. Ordered implementation work

### 1 — Record approval and preserve the starting point

Record Boss's API/endpoint/replay/collection decisions in these docs, reconciling
all three documents if a decision changes. If exact overloaded spellings win,
revise the call/tooling design before implementation; do not quietly engineer the
named alternative. Inventory current worktree changes and protected historical
evidence. Preserve the existing unexplained filesystem and optimizer incidents.

Before executing new generated VOID fixtures, connect the existing crash wrapper
and validate preservation. Keep exact generated bytes alive until subprocess
completion; retain command, cwd, status, output, binary hash, generator and imports.

### 2 — Add only the private deterministic compiler primitives

Model canonical `/@stdlib/random.void` gating on
`src/frontend/binary_codec.inc` and its call dispatch in `compiler.cpp`.

- `_random_domain_max<t>()`: accept exactly eight integers using existing numeric
  metadata, produce existing u64 constant IR, reject unsupported specializations
  at their actual call sites. No public numeric trait/reflection system.
- `_random_xor(u64,u64)`: new narrow runtime-only scalar operation, typed IR
  definition/validation, lowering to LLVM XOR, pure effects. Add no parser glyphs,
  shift operations, native state ABI or arbitrary constant-call support.
- Keep semantic handlers outlined like the current numeric/binary helpers rather
  than enlarging recursive frontend frames with substantial new local state.

Touch existing frontend/IR/backend seams, preferably a small matching include
where warranted; do not introduce a parallel builtin engine. Verify direct and
spoofed project access rejects, malformed IR rejects, ordinary u64 behavior is
unchanged, and pure deterministic use remains allowed inside worker graphs.

### 3 — Implement one source engine and explicit generator ownership

Add `stdlib/random.void` with the common error import, algorithm-version constant,
four private u64 state fields and required seed initializer. Implement SplitMix64
mixing and the fixed xoshiro256** transition in source using XOR plus existing
wrapping arithmetic. Preserve exact transition order and decimal constants.

Implement Boolean, eight full integer draws, f32/f64 unit draws and explicit
receiver reseeding. Share one raw-word method. State-changing helpers must mutate
the selected generator receiver, not discard an ordinary parameter copy.

Verify raw vectors, copied generator positions, reseeding, readonly/temporary
rejection, required construction, and successful generation without OS entropy.
No new native support is needed for these deterministic operations.

### 4 — Complete integer range/error families

Implement shared ordinal encode/decode, candidate extraction and unbiased
rejection using u64 intermediates. Then expose all eight one/two-bound rand_T families,
their checked forms and generic inclusive rand_range/try_rand_range. Reuse common
validation and receiver sampling; do not duplicate eight samplers.

Add the proposed derived managed error and portable kinds/codes. Use existing
convert.unwrap for authority-compatible plain wrappers. All validations precede state advancement.
Singleton success uses no word. Full inclusive u64/i64 must never divide by zero,
cast a negative signed value to u64 or compute `max+1` in the source type.

Verify every width, arity and signedness, equivalent full-domain/raw calls, all invalid
and singleton cases, forced rejection, exact generic inference and source-located
plain failure with normal cleanup.

### 5 — Complete finite float ranges

Implement finite validation, sign-aware scaling and ordered accept/retry in source
for both precisions. Add one/two-bound rand_T checked/plain functions without a new
predecessor, epsilon or floating native kernel. Preserve operation precision,
evaluation order and unit-grid extraction under O2.

Verify endpoints, nonfinite/reversed/equal errors, adjacent/subnormal intervals,
both zero signs, opposite finite extremes and a forced rejected upper endpoint
followed by an accepted draw. Test bit patterns, not only formatted decimal text.
Pin any new bounded/mixed vectors independently. Do not add a retry cap.

### 6 — Complete generic collection operations

Implement choose, descending Fisher–Yates shuffle and full-slice shuffled using
ordinary growable lists. Reuse the i64 bounded sampler. Choose variants share a
checked scalar index helper; unwrap the index, not readonly element results.
Implement generator.shuffled's short traversal locally on its slice, avoiding
the mutable generic shuffle parameter boundary. Module copy variants initialize
readiness using scalar results then directly return that generator copy/Ok.
No-draw cases skip default initialization. No readonly generic syntax is added.

Test aliases, duplicates, empty/singleton lists, fixed-array slice callers,
managed identity, inline/fixed element copies, nested readonly capability and GC
between swaps. Nonstructural swaps must not change count/structural version.
Verify const-input choose/copy returns readonly child references even from a
mutable original, and public shuffle rejects incompatible readonly-child profiles.
Exercise a complex-element allocation failure without claiming transactional
in-place rollback. Copy-returning failure must leave the original outer list
unchanged. No direct generic fixed-array mutation extension.

### 7 — Add the single checked entropy boundary

Add a small Runtime source/ABI declaration and JIT symbol binding at the existing
`runtime_abi.hpp`, Runtime target and LLVM backend seams. Use native scalar stack
output and the existing failure context, with a distinct OS status channel.
Enter NativeSafe for the OS call; re-enter Managed before constructing results.

- Linux: exact eight-byte getrandom request, EINTR/short/zero/error handling.
- Windows: system-preferred BCryptGenRandom and preserved NTSTATUS. Add bcrypt
  Runtime linkage **and** existing `cmake/NativeBuild.cmake` installed flags.
- macOS: eight-byte getentropy, errno, supported deployment availability.

Decode little-endian and call the same source initializer. Do not add a provider
handle, file descriptor, worker job or clock/hash fallback. Reject entropy in
frontend effect propagation and independent worker IR validation. Keep checking,
LSP, seeded-only execution and cache population entropy-free.

Test through the narrow native seed boundary with a deterministic local stub for
OS success, failure, zero seed, interrupted/short reads and output nonpublication.
Keep test substitution at the existing target/link seam or a tiny local test
seam, never a public environment-variable backend/entropy framework. Verify OS
failure versus Runtime failure separately. Genuine native success is also needed.

### Independent oracles and statistical sanity

Retain a small development-only arbitrary-precision reference model, with constants
and expected bytes checked against the published core plus independent vectors.
It must not import the implementation to create its expected results. Verify
small-domain accepted residue counts exhaustively and supply deterministic raw
candidates to drive both rejection and no-rejection paths. A tiny private pure
sampler test seam is sufficient; no production-pluggable RNG interface is needed.

Use fixed seeds for modest histograms of Boolean and non-power-of-two integer
bounds, unit-float means/buckets and positions in a small shuffle. Choose generous,
documented sanity tolerances from sample sizes, then pin results after independent
review. These checks can catch stuck state/obvious bias; they do not certify
statistical quality or cryptographic security and must not make CI probabilistic.
Never use wall-clock-seeded pass/fail assertions or collision-free expectations.

Measure one representative local run of raw/typed/bounded draws and small-list
shuffle, reporting throughput and allocation behavior with compiler configuration.
Confirm no per-draw binary-codec arrays/native generator allocations. Investigate
only demonstrated regressions; no benchmark framework, speculative cache or LTO
configuration change belongs in this module mission.

## 4. Mandatory crash preservation

Every abnormal compiler/runner exit must retain the **exact** source that was
executed, named `*_crash.void`, before temporary cleanup, retry or reduction.
Reuse `tests/text_encoding/crash.py` and the io preservation regression. Supply
source_inputs for linked executables and generators, imports and unsaved LSP
overlays as applicable; a binary pathname alone is not enough to recover source.

Preserve a unique incident directory, matching input/preserved SHA-256, executable
hash, command/cwd/environment selection, status/signal, stdout/stderr and generator
provenance. Never overwrite an incident or reconstruct source later and call it
original. Expected ordinary compile/runtime diagnostics are not crashes.
Signals, native exception status and strict sanitizer exits already have wrapper
support. Explicitly preserve unexpected internal exits/timeouts at the harness
boundary too: the current `run` wrapper does not automatically preserve every
TimeoutExpired exception. Extend/reuse that small boundary only as needed, not
a new validation framework. If a crash occurs, stop the affected run, preserve it
and report; do not silently retry until green or classify it as an LLVM bug.
