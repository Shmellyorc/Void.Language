## Redistribution requirements and gaps

**LLVM and permissive code.** Supply the exact [23.1.4 LICENSE.TXT](https://raw.githubusercontent.com/llvm/llvm-project/llvmorg-23.1.4/LICENSE.TXT), relevant subcomponent texts and required notices with each independently distributed tool. Apache requires the license, relevant NOTICE attribution and modification notices where applicable. Its LLVM exception addresses code embedded through compilation; it is not a blanket exemption for shipping an LLVM-linked compiler. No general corresponding-source requirement follows from this permissive route. The license itself directs distributors to additional file/directory terms. For BLAKE3 use its [exact tagged license](https://raw.githubusercontent.com/llvm/llvm-project/llvmorg-23.1.4/llvm/lib/Support/BLAKE3/LICENSE).

The complete SDK is a separate scope: inventory any shipped `clang`, LLD, LLVM libraries, headers, Clang resource headers, compiler-rt, libc++/libc++abi, unwind libraries and bundled third parties against the exact archive. Do not assume these are all present, used or covered by one notice. Keep the SDK external initially to avoid this extra payload; attribution for LLVM already embedded in VOID still applies. [zstd's BSD text](https://raw.githubusercontent.com/facebook/zstd/v1.5.7/LICENSE) and [libxml2's Copyright](https://raw.githubusercontent.com/GNOME/libxml2/v2.15.4/Copyright) confirm their notice requirements. MIT/ISC/BlueOak and curl notices must accompany the covered copied material; source distributions must retain source-level notices too.

**GNU shared libraries.** The checked-in [LGPLv3 text](../../third_party/http-licenses/libidn2-2.3.8/COPYING.LESSERv3), together with GPLv3, requires prominent library-use attribution, both license texts, and terms permitting modification and reverse engineering to debug library changes. Section 4 provides alternative combined-work mechanisms: suitable shared-library replacement, or the required application material for relinking. Choosing shared libraries does not remove the source obligations for the library binaries themselves. Conditional Installation Information requirements also need assessment for the chosen delivery model.

Both source archive hashes pass, and a build receipt records commands. However, installed provisioning scripts derive a repository root from `__file__` and expect repository paths/toolchains, not their installed `corresponding-source` layout. Supply complete corresponding source, applicable patches/configuration/build scripts and usable instructions through a compliant delivery method. Archive presence alone is insufficient proof; a mutable upstream link alone is not a source-delivery plan.

[NativeInventory.cmake](../../cmake/NativeInventory.cmake) hashes GNU shared resources; [native_build.cpp](../../src/native_build.cpp) rejects mismatches before native linking. The manifest is editable, not cryptographically locked. Document and review an ABI-compatible replacement plus manifest-update procedure for `voidc` and generated applications; do not infer either compliance or a violation solely from hashing. No replacement experiment or code change was performed. Counsel should assess the selected license route, application terms, source completeness and any installation-information duty.

**PSL and generated applications.** [MPL §§3.1–3.4](https://www.mozilla.org/en-US/MPL/2.0/) require covered source availability, notice preservation and recipient information; MPL permits a larger work under other terms. Installed PSL source supports that duty without automatically putting all VOID under MPL. Applications containing VOID runtime/third-party code need their own applicable notice/source instructions. LLVM's exception does not grant rights to VOID's runtime or erase HTTP dependencies' obligations.
