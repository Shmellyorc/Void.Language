**VOIDUP Phase B engineering report — private review, 2026-11-06/07**

VOIDUP is now a native application written in VOID. It installs authenticated real toolchains, verifies their complete inventories, changes the active selection atomically, rolls back, and launches the selected compiler or language server. All installation decisions are in [apps/voidup](../../apps/voidup/main.void). The bootstrap is built by `voidc`; Python is used only for development packaging, offline fixture signing and qualification. There is no Python installer at runtime.

The only production native addition in this phase is the ordinary read-only `io.file.private_mode_matches(executable)` primitive. Verification needed to detect removed execute permission without changing an existing file. It inspects the same held regular file, ownership, single-link identity and private access policy. POSIX checks exactly `0700` versus `0600`, including rejection of extra mode bits; Windows checks its protected private DACL because it has no POSIX execute-bit classification. Its admitted host operation was appended, preserving previous operation ordinals. Existing compiler admission, IR validation, managed roots, Runtime ledger and native ABI machinery are reused. No new language syntax, scheduler, native-handle escape or native installer policy was added. A separate `EXCLUDE_FROM_ALL` CMake target embeds the source application for explicit GC/fault qualification; it adds no default CI/CTest work.

Actual CLI behavior is:

| Command | Result |
| --- | --- |
| `--help`, `--version` | No managed root or network access; version identifies private engineering trust. |
| `list` | Installed records, real build identities, current/previous and retained revocation flags; offline. |
| `list --available` | Authenticates a fresh explicitly selected catalog and commits its trust floor before displaying host-compatible releases. |
| `install ID [--activate]` | Authenticates catalog, inventory and package, extracts through held capabilities, publishes without replacement, registers, optionally activates. An already published version is reused only after complete signed verification. Conflicting bytes under an installed ID are rejected. |
| `default ID`, `rollback` | Verifies the selected complete prefix, then atomically replaces one control file containing both current and previous. Rollback changes selection, never serial/revocation history. |
| `which voidc\|voidls` | Verifies the default prefix and prints its absolute tool path. |
| `verify ID` | Reauthenticates retained proof and hashes every member; rejects wrong modes, missing/extra members, links, identity mismatch and known revocation. |
| `doctor` | Verifies all nonrevoked registered prefixes, diagnoses trust/current/previous/retained transactions, and attempts native directory sync. |
| `run ID\|default voidc\|voidls -- ...` | Verifies the complete prefix and rehashes the held tool, releases the writer lock, launches its absolute path with literal arguments and a controlled environment, inherits streams, and returns the child status. POSIX signal termination maps to `128 + signal`. |

Global options precede the command: `--root ABSOLUTE-PATH`, `--catalog HTTPS-URL`, `--ca-file PEM`, `--timeout-ms 100..120000` (default 30000). Repeated global options, extra operands and missing `--` are invocation errors (status 2). Recoverable policy/native errors use status 1 and JSON containing message, operation, portable kind, available HTTP phase/status, native domain/code, cleanup code, exact available progress, and `published`/`durable`. Native kind/phase names use the existing enum display contract. A library deadline can correctly have native code zero; its portable timeout kind and download phase are retained. Successful `run` preserves child status, including the measured status 17. The application inherits no caller PATH, loader injection or compiler override variables into the child. Its explicit PATH contains the selected bundled SDK and declared system directories; executable selection itself never uses PATH. LSP needs its existing `--entry PROJECT.void` argument.

An existing root must be private and contain the exact initialized VOIDUP marker. Unknown directories are rejected before lock-file creation, adoption, chmod or deletion. Missing parents are exclusively created through the approved native primitives. Group-writable checkout ancestors are deliberately refused. Version/control/cache operations hold the native writer lock. Transactions and versions remain on the root's filesystem. Every extracted file is hashed/CRC-checked, classified and flushed; nested directories are synchronized before payload publication. Catalog/inventory proof is published before referring control state. The highest accepted serial, digest, time and monotonically accumulated revocations are committed before later downloads can fail. A published-but-unregistered payload can be registered on a later authenticated install only after full verification.

There is no pruning. Failed, interrupted and completed download transactions are retained, including uncertain publication outcomes. The manager never infers lock ownership from a leftover lock file, recursively deletes unknown content, replaces an existing version, or claims that a post-rename failure restored the old selection. A successful rename followed by sync failure returns `published=true, durable=false`; the next invocation reads and verifies actual state. Native directory sync acknowledgments cannot prove hardware power-loss durability. Initial root creation also makes no independently measured power-loss claim.

The trust contract uses raw catalog bytes prefixed by `VOIDUP CATALOG v1\n`, then detached Ed25519 endorsements. The envelope is bounded to 4 KiB, schema 1, 2–3 known distinct key IDs, and exact 64-byte signatures. At least two trusted endorsements must verify before catalog decoding. The catalog's signed SHA-256 and exact byte length authenticate each inventory and artifact. Catalog validity is bounded to 30 days, future issuance tolerance to 300 seconds, and the retained clock/serial floor rejects replay or same-serial equivocation. Removing a retained revocation is rejected. Local control and proof corruption fails closed. Offline installed use reauthenticates signed bytes without requiring the old installation catalog to remain unexpired; it applies all *known* retained revocations. `run` does not silently contact a server for newer revocations.

Limits are local upper bounds, never enlarged by a catalog: 8 MiB metadata, 2 GiB package, 1 GiB member, 4 GiB expanded bytes, 20,000 members, 64 releases/installed records, 1,024 revocations and 256 retained transaction directories. Paths have at most 16 components/4,096 bytes, each at most 255 bytes, with portable ASCII components, declared directory ancestors, case-collision/traversal/Windows-reserved-name checks and no links/special files. Transfers have finite deadlines. Hashing/extraction uses 256 KiB blocks. Metadata caches are retained; there is no implemented aggregate cache/disk quota or pruning policy. Repeated authenticated catalog revisions can therefore grow disk usage even though each operation is bounded. JSON uses explicit depth/node/string/work budgets.

Failures were retained before repair:

1. Early source checks exposed exact error-type propagation requirements, unsupported array `+=`, imported-name shadowing, result handling and import visibility mistakes. The source was corrected to use explicit checked adapters and the established language APIs. Compiler diagnostics remain in the first/lift/storage/inventory/manager check logs; no successful acceptance was fabricated from them.
2. Fixture production encountered a directory symlink in CMake-installed corresponding-source material. The first producer tree and traceback remain; production now materializes both directory and file aliases before inventory/signing.
3. The initial root beneath this group-writable checkout was refused. Qualification moved to exclusively owned private directories; the refusal remains recorded. No native permission check was relaxed.
4. An argument fixture used nonexistent `console.writeln`, the LSP fixture omitted its required `--entry`, and the first portable-source reruns selected the verbose native child helper instead of `void_host_portable`. Original outputs remain; corrected fixtures exercise the actual interfaces.
5. The first bootstrap, linked on PikaOS despite using the Ubuntu compiler, required `GLIBC_2.42` and failed on Ubuntu. Rebuilding it inside Ubuntu repaired the compatibility error; the original failed run and the subsequent Ubuntu success remain.
6. The first fsync injection library path contained spaces, which ELF `LD_PRELOAD` splits. Its warning and unexpectedly successful activation remain recorded. The injection library moved to an exclusively created whitespace-free test path; real pre/post-publication failures were then observed. This test helper is never linked into VOIDUP.
7. The first allocation sweep exhausted its budgets during initial generation setup. Warmup moved injection into application execution. A later forced-GC sweep deliberately faulted GC's temporary allocations; the generic probe unconditionally terminated on its documented `Collection::allocation_failure`. GDB located `vd_gc_construct_typed`. The application-specific probe now counts that recoverable collection failure, still forces real collections and inspects precise roots/commit balance, and retries the unchanged source application after each fault. The abort and source copies remain; production Runtime behavior was not changed to hide it.
8. Intentional SIGKILL probes retain exact app/stdlib inputs and are labeled as intentional crash/recovery evidence. Expected TLS peer-disconnect tracebacks after killing a client also remain. They are not silently discarded or counted as native application crashes.
9. Final source review added a second clock-floor check after potentially long prefix verification and before changing selection. A clock adjustment during hashing must not lower the retained time floor. The final Ubuntu bootstrap, selection/isolation checks and normal/O2 profile reruns include that guard; no host clock was changed during qualification.
10. The first deadline assertion incorrectly required a nonzero native code for a library-owned deadline. Its original output remains. That test also exposed a real application defect: the adapters dropped the available portable error kind/phase, and response-count policy errors dropped available HTTP status/progress. The adapters now preserve them without inventing native codes. The final deadline and truncated-package cases validate exact progress and classification. `private-key-exclusion-final.json` also verifies that the final binary contains none of the exact offline test private seeds; the unchanged package scan is retained separately.
